## Лабораторная работа №3: Валидация данных в форме
* **Страница задания:** [laba03 (2024)](https://slavaver.github.io/web-course-site/labs/client-side-basics/full-time/2024/laba03/)
* **Ветка Git:** `lab3`
* **Ключевой функционал:**
  - Интеграция шапки и стилей из макета прошлого семестра («Doctor Toma»).
  - Добавлена кнопка «Регистрация» в навигацию шапки и секцию hero.
  - Нативное модальное окно на базе элемента `<dialog>` (открытие через `showModal()`).
  - Закрытие окна по кнопке «Закрыть» (`&times;`), кнопке «Отмена» и при клике вне содержимого диалога (по подложке `::backdrop`).
  - Форма с полями: имя, email, пароль (≥ 6 символов). Атрибут `novalidate` для формы.
  - Обязательность заполнения указана текстом в `<label>` (без звёздочек).
  - Стилизация состояний с помощью псевдоклассов `:user-valid` и `:user-invalid`.
  - Валидация при потере фокуса (`blur`) с проверкой через интерфейс `validity` (Constraint Validation API).
  - Доступность (A11y): элементы сообщений об ошибках связаны через `aria-describedby`, имеют `aria-live="polite"` и скрыты через атрибут `hidden` до возникновения ошибки; при ошибке добавляется `aria-invalid="true"`.
  - Кнопка показа пароля: удерживание (`pointerdown` и `pointerup`) временно меняет тип поля с `password` на `text`.
  - Обработка `submit`: при наличии ошибок фокус ставится на первое неверное поле; при успехе данные собираются через `FormData()` и выводятся в консоль браузера.

## Лабораторная работа №5: Fetch API и Storage
* **Страница задания:** [laba05 (2024)](https://slavaver.github.io/web-course-site/labs/client-side-basics/full-time/2024/laba05/)
* **Сервер данных:** `http://95.163.242.125` (актуальный рабочий сервер курса)
* **Ветка Git:** `lab5`
* **Ключевой функционал:**
  - Заголовок H1: «Беляков Игорь - Лабораторная работа №5».
  - **Переключение тем (Light / Dark):**
    - Хедер с кнопкой переключения темы.
    - Сохранение выбранной темы в `localStorage`.
    - Устранение мерцания темы (FOUC) с помощью инлайн-скрипта в `<head>`, применяющего `data-theme` до отрисовки `<body>`.
  - **Компонент Toast-уведомлений:**
    - Расположен в правом нижнем углу страницы (`bottom: 24px; right: 24px`).
    - Плавное появление (slide-in) и скрытие (slide-out).
    - Разные стили: красный фон для ошибок (`role="alert"`), зелёный фон для сообщений (`role="status"`).
    - Закрытие по кнопке «&times;» и автоматическое скрытие по таймеру.
    - Адаптивность и высокий контраст.
  - **Секция Галереи:**
    - Эндпоинт `GET /images`.
    - Загрузка картинок при открытии страницы и по кнопке «Обновить галерею».
    - Индикатор загрузки (Spinner) во время ожидания ответа.
    - Механизм повтора запроса (retry): до 3 попыток с небольшой паузой в случае сбоя или статуса 500.
    - Если ответ пустой (0 картинок), выводится надпись «Изображения не найдены».
    - При неудаче всех 3 попыток выводится сообщение об ошибке и уведомление в toast.
    - Сетка изображений на CSS Grid: ровно 4 карточки в ряд на десктопе, одинаковый размер карточек и аккуратная обрезка (`object-fit: cover`).
  - **Секция Температуры:**
    - Эндпоинт `POST /temp` с заголовком `Content-Type: application/json`.
    - Форма ввода номера аудитории (строка) и температуры (число).
    - Блокировка полей и кнопки во время отправки запроса.
    - При успехе (200 OK): вывод сообщения из ответа сервера через зелёный toast и очистка формы.
    - При ошибке: вывод текста ошибки в красный toast, форма при этом **не** очищается.
