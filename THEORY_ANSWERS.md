
## Лабораторная работа №1: JS: синтаксис

### 1. Что значит «JS слабо типизированный язык»?
Слабая (или нестрогая) типизация означает, что язык допускает неявное автоматическое приведение типов в выражениях с разными типами данных. При выполнении операций интерпретатор JavaScript не выдаёт ошибку несоответствия типов, а пытается самостоятельно преобразовать один тип к другому по внутренним правилам спецификации ECMAScript:
* Например, сложение числа со строкой `5 + "10"` вернёт строку `"510"` (число приводится к строке).
* Вычитание `"20" - 5` вернёт число `15` (строка приводится к числу).
* Сравнение `0 == false` вернёт `true` из-за неявного приведения к числовому значению.

### 2. Что значит «JS язык с динамической типизацией»?
Динамическая типизация означает, что тип данных привязывается к самому **значению**, а не к переменной. Типы данных проверяются во время выполнения программы (runtime), а не во время компиляции.
* Переменная, объявленная через `let` или `var`, может в разное время хранить значения любых типов:
  ```javascript
  let data = 42;        // сейчас это number
  data = "Привет";      // теперь это string
  data = { id: 1 };     // теперь это object
  ```
* В отличие от языков со статической типизацией (C++, Java, TypeScript), здесь не требуется заранее объявлять тип переменной при её создании.

### 3. Типы значений в JS. Оператор определения типа.
В современном стандарте JavaScript существует **8 базовых типов данных**:
1. **Примитивные типы (7 типов):**
   * `number` — числовые значения (целые и с плавающей точкой в формате IEEE 754, а также специальные числовые значения: `NaN`, `Infinity`, `-Infinity`).
   * `bigint` — целые числа произвольной длины (суффикс `n` в конце, например `9007199254740991n`).
   * `string` — текстовые строки.
   * `boolean` — логический тип (`true` или `false`).
   * `null` — специальное значение, обозначающее осознанное «отсутствие значения» или «пустоту».
   * `undefined` — значение переменной, которой ещё не было присвоено значение, либо отсутствие возвращаемого значения.
   * `symbol` — уникальный и неизменяемый идентификатор (используется для скрытых свойств объектов).
2. **Сложный (ссылочный) тип:**
   * `object` — коллекции данных и сложные структуры (включая массивы `Array`, функции `Function`, даты `Date`, регулярные выражения `RegExp` и т.д.).

**Оператор определения типа:** `typeof`
```javascript
typeof 42;              // "number"
typeof "текст";         // "string"
typeof true;            // "boolean"
typeof undefined;       // "undefined"
typeof Symbol("id");    // "symbol"
typeof 10n;             // "bigint"
typeof { a: 1 };        // "object"
typeof [1, 2, 3];       // "object" (массив является объектом)
typeof function() {};   // "function" (специальный случай для удобства)
typeof null;            // "object" (официально признанная историческая ошибка первой версии JS)
```

### 4. Чем отличаются строки в `""`, `''` и `` ` ``?
* **Одинарные `''` и двойные `""` кавычки:**
  * Абсолютно эквивалентны по функционалу.
  * Не поддерживают многострочный текст без экранирования переноса строки (`\n`).
  * Не поддерживают интерполяцию переменных и выражений.
* **Косые кавычки `` ` `` (шаблонные литералы / Template Literals, появились в ES6):**
  1. **Интерполяция:** позволяют встраивать любые выражения и переменные прямо внутрь строки с помощью синтаксиса `${выражение}`:
     ```javascript
     const name = "Игорь";
     console.log(`Привет, ${name}! Результат: ${2 + 2}`); // Привет, Игорь! Результат: 4
     ```
  2. **Многострочность:** сохраняют все реальные переносы строк и отступы без символа `\n`.
  3. **Тегированные шаблоны (Tagged Templates):** позволяют вызывать функции-обработчики шаблонов (например, `styled.div\`...\``).

### 5. Операнд и оператор.
* **Оператор (Operator):** символ или ключевое слово, выполняющее определённое действие или вычисление (например, `+`, `-`, `*`, `&&`, `typeof`, `delete`).
* **Операнд (Operand или аргумент):** то, к чему применяется оператор. Например, в выражении `5 * 2`:
  * `5` — левый операнд;
  * `2` — правый операнд;
  * `*` — оператор умножения.

### 6. Примеры унарных, бинарных и тернарного оператора в JS.
* **Унарный оператор (Unary):** принимает ровно **один** операнд:
  * Унарный плюс `+`: `+"42"` (быстрое приведение строки к числу `42`).
  * Унарный минус `-`: `-x` (меняет знак числа на противоположный).
  * Логическое НЕ `!`: `!true` (`false`), `!!"текст"` (`true`).
  * Инкремент/декремент: `++count`, `i--`.
  * Оператор `typeof`: `typeof x`.
* **Бинарный оператор (Binary):** принимает ровно **два** операнда:
  * Сложение: `a + b`.
  * Сравнение: `x > y`, `a === b`.
  * Логические И/ИЛИ: `isValid && isReady`, `role || "guest"`.
  * Присваивание: `x = 10`.
* **Тернарный оператор (Ternary):** принимает **три** операнда (единственный в JS — условный оператор `? :`):
  ```javascript
  const status = age >= 18 ? "совершеннолетний" : "несовершеннолетний";
  ```

### 7. Истинные и ложные значения в JS.
В логическом контексте (например, в условиях `if(...)`) любое значение неявно приводится к логическому типу (`boolean`).
* **Ложные значения (Falsy values) — их ровно 8:**
  1. `false`
  2. `0` (число ноль)
  3. `-0` (отрицательный ноль)
  4. `0n` (BigInt ноль)
  5. `""` (пустая строка)
  6. `null`
  7. `undefined`
  8. `NaN` (Not a Number)
* **Истинные значения (Truthy values):**
  * Все остальные значения, включая `"0"` (непустая строка), `"false"`, `[]` (пустой массив), `{}` (пустой объект), функции и отрицательные числа (`-1`).

### 8. Циклическое исполнение кода в JS.
Для многократного повторения инструкций в JS применяются следующие конструкции:
1. `for (инициализация; условие; шаг)` — классический цикл со счётчиком:
   ```javascript
   for (let i = 0; i < 5; i++) { console.log(i); }
   ```
2. `while (условие)` — цикл с предусловием (выполняется, пока условие истинно; тело может не выполниться ни разу):
   ```javascript
   while (n > 0) { n--; }
   ```
3. `do ... while (условие)` — цикл с постусловием (тело гарантированно выполнится хотя бы один раз):
   ```javascript
   do { input = prompt(); } while (!input);
   ```
4. `for ... of` — цикл для перебора значений итерируемых коллекций (массивов, строк, Map, Set).
5. `for ... in` — цикл для перебора перечисляемых строковых ключей/свойств объекта.
* Для управления циклом используются операторы:
  * `break` — немедленно прерывает выполнение цикла.
  * `continue` — прерывает текущую итерацию и переходит к следующей.

### 9. Создание функций в JS. Сигнатура функции.
В JavaScript существует три основных способа объявления функций:
1. **Function Declaration (Объявление функции):**
   ```javascript
   function sum(a, b) {
     return a + b;
   }
   ```
   * *Особенность:* всплывает (hoisting), функцию можно вызвать в коде выше места её объявления.
2. **Function Expression (Функциональное выражение):**
   ```javascript
   const sum = function(a, b) {
     return a + b;
   };
   ```
   * *Особенность:* создаётся в момент выполнения выражения, доступна только после него.
3. **Arrow Function (Стрелочная функция, ES6):**
   ```javascript
   const sum = (a, b) => a + b;
   ```
   * *Особенность:* краткий синтаксис, не имеет собственного контекста `this`, аргументов `arguments`, `super` и конструктора `new`.

* **Сигнатура функции (Function Signature):** включает имя функции, количество и типы её параметров, а также тип возвращаемого значения. В динамическом JS сигнатура не фиксируется жестко на уровне компилятора, но логически описывает интерфейс взаимодействия с функцией (например, `calculateTotal(price: number, taxRate?: number): number`).

### 10. Параметры функции и аргументы.
* **Параметры (Parameters):** переменные, перечисленные в круглых скобках при объявлении функции. Это формальные имена ожидаемых данных (например, `a` и `b` в `function add(a, b)`).
* **Аргументы (Arguments):** фактические значения, которые передаются в функцию в момент её вызова (например, `5` и `10` в вызове `add(5, 10)`).
* Дополнительно в ES6 доступны:
  * Параметры по умолчанию: `function greet(name = "Гость") { ... }`
  * Rest-параметры (остаточные параметры): `function fn(first, ...rest) { ... }`

### 11. Концепт «раннего возврата» из функции (Early Return).
**Ранний возврат (Early Return / Guard Clauses):** подход к написанию функций, при котором проверка пограничных условий, невалидных данных или ошибок происходит в самом начале функции, после чего сразу выполняется оператор `return`.
* *Преимущество:* избавляет код от глубокой вложенности блоков `if-else` (так называемой «пирамиды спагетти-кода»), делает функцию линейной и лёгкой для чтения:
  ```javascript
  // Плохо: глубокая вложенность
  function processUser(user) {
    if (user) {
      if (user.isActive) {
        // основная логика
      }
    }
  }

  // Хорошо: ранний возврат
  function processUser(user) {
    if (!user) return;
    if (!user.isActive) return;

    // Основная логика выполняется прямо на верхнем уровне
  }
  ```

### 12. Как можно перебирать элементы массива?
1. Цикл `for (let i = 0; i < arr.length; i++)` — классический доступ по индексу.
2. Цикл `for (const item of arr)` — современный лаконичный обход значений.
3. Метод `arr.forEach((item, index, array) => { ... })` — декларативный перебор с функцией обратного вызова (не прерывается через `break`).
4. Методы трансформации и поиска: `map()`, `filter()`, `reduce()`, `some()`, `every()`, `find()`, `findIndex()`.
5. Итераторы: `arr.entries()`, `arr.keys()`, `arr.values()`.

### 13. Методы массива filter, map, reduce.
* **`filter(callback)`:**
  * Возвращает **новый массив**, содержащий только те элементы исходного массива, для которых callback вернул истинное (`truthy`) значение. Длина нового массива $\le$ длине исходного.
  * Пример: `[1, 2, 3, 4].filter(x => x % 2 === 0); // [2, 4]`
* **`map(callback)`:**
  * Возвращает **новый массив той же длины**, полученный путём применения callback-функции к каждому элементу исходного массива.
  * Пример: `[1, 2, 3].map(x => x * 2); // [2, 4, 6]`
* **`reduce(callback, initialValue)`:**
  * Последовательно сворачивает (агрегирует) массив в **одно итоговое значение** (число, строку, объект, массив). На каждом шаге передаёт аккумулятор и текущий элемент:
  * Пример (сумма): `[1, 2, 3, 4].reduce((acc, curr) => acc + curr, 0); // 10`

### 14. Объекты. Создание, ключи, значения, свойства.
* **Объект в JS:** ассоциативный массив (хеш-таблица), хранящий пары «ключ: значение».
* **Создание:**
  * Литерал объекта (предпочтительный способ): `const obj = { name: "Иван", age: 20 };`
  * Конструктор: `const obj = new Object();`
  * Метод создания с прототипом: `Object.create(proto);`
* **Ключи (Keys):** имена свойств, могут быть только строками (`string`) или символами (`symbol`). Любой другой тип автоматически преобразуется в строку.
* **Значения (Values):** данные любого типа (включая примитивы, другие объекты и функции — такие функции называются *методами*).
* **Свойства (Properties):** пара «ключ + значение» плюс внутренние дескрипторы флагов (`writable`, `enumerable`, `configurable`).

### 15. Как получить значение из свойства объекта?
1. **Точечная нотация (`obj.prop`):**
   * Применяется, когда имя свойства известно заранее и является корректным идентификатором JS (не содержит дефисов, пробелов и не начинается с цифры).
   * Пример: `user.name;`
2. **Скобочная нотация (`obj["prop"]`):**
   * Обязательна, если имя свойства хранится в переменной, содержит спецсимволы, пробелы или дефисы:
   * Пример: `user["first-name"]`, `const key = "age"; user[key];`
3. **Деструктурирующее присваивание (ES6):**
   * `const { name, age } = user;`
4. **Опциональная цепочка `?.` (Optional Chaining):**
   * Безопасное чтение глубоких вложенных свойств без падения с ошибкой `TypeError`, если промежуточный объект `null` или `undefined`:
   * Пример: `user?.address?.city;`

## Лабораторная работа №2: DOM и события

### 1. Назначение .gitignore и ESLint
* **`.gitignore`:** текстовый файл конфигурации системы контроля версий Git. Он указывает Git, какие файлы, папки и системные артефакты не нужно отслеживать и добавлять в репозиторий (например, тяжёлая папка зависимостей `node_modules/`, файлы переменных окружения `.env`, временные файлы ОС `.DS_Store`, `Thumbs.db`, логи и сборки `dist/`).
* **ESLint:** статический анализатор кода (линтер) для JavaScript. Его назначение:
  * Находить синтаксические ошибки и потенциальные баги до запуска программы.
  * Обеспечивать соблюдение стандартов написания кода (style guide) в команде.
  * Автоматически форматировать код и предотвращать использование устаревших/опасных конструкций (например, необъявленные переменные, забытые console.log, неиспользуемые переменные).

### 2. window, DOM, BOM.
* **`window`:** глобальный объект в среде выполнения браузера. Он выполняет две роли:
  1. Является глобальной областью видимости для JavaScript-кода (все глобальные переменные и функции становятся его свойствами).
  2. Представляет окно браузера и предоставляет доступ к DOM и BOM.
* **`DOM` (Document Object Model — Объектная модель документа):** древовидное представление содержимого HTML-страницы в виде объектов, с которыми JS может взаимодействовать (изменять разметку, теги, атрибуты, текст и стили). Точка входа — объект `document`.
* **`BOM` (Browser Object Model — Объектная модель браузера):** набор объектов, предоставляемых браузером для работы со всем, что не относится к самой структуре документа HTML:
  * `navigator` — сведения о браузере, ОС, геолокации.
  * `location` — текущий URL страницы, управление перенаправлениями и перезагрузкой.
  * `history` — история переходов текущей вкладки (`history.back()`, `history.pushState()`).
  * `screen` — характеристики дисплея пользователя (разрешение, глубина цвета).
  * Диалоговые окна: `alert()`, `confirm()`, `prompt()`.

### 3. DOM-дерево, навигация и поиск.
HTML-документ представляется браузером как иерархическое дерево узлов (Node Tree), где каждый тег, текст и комментарий являются узлами.
* **Навигация по узлам (включая пробелы и переводы строк):**
  `parentNode`, `childNodes`, `firstChild`, `lastChild`, `nextSibling`, `previousSibling`.
* **Навигация только по элементам-тегам (Element):**
  `parentElement`, `children`, `firstElementChild`, `lastElementChild`, `nextElementSibling`, `previousElementSibling`.
* **Методы поиска элементов в DOM:**
  * `document.querySelector(selector)` — возвращает **первый** элемент, соответствующий CSS-селектору (или `null`).
  * `document.querySelectorAll(selector)` — возвращает статическую коллекцию `NodeList` со всеми подходящими элементами.
  * `document.getElementById(id)` — быстрый поиск элемента по значению `id`.
  * `element.closest(selector)` — поиск ближайшего предка, удовлетворяющего селектору (включая сам элемент).
  * `element.matches(selector)` — проверяет, удовлетворяет ли элемент селектору (возвращает `true/false`).

### 4. Классы DOM-узлов.
Иерархия классов в DOM построена на прототипном наследовании:
1. **`EventTarget`** — базовый корневой класс, дающий узлам возможность подписываться на события и генерировать их (`addEventListener`, `removeEventListener`, `dispatchEvent`).
2. **`Node`** — наследует `EventTarget`, базовый класс для всех узлов дерева. Содержит свойства `nodeType`, `nodeName`, `parentNode`, `childNodes`, `textContent`.
3. **`Element`** — наследует `Node`, базовый класс для элементов (тегов). Предоставляет методы навигации по элементам (`children`), работу с атрибутами (`getAttribute`, `setAttribute`) и поиск (`querySelector`).
4. **`HTMLElement`** — базовый класс для всех HTML-элементов (добавляет свойства `hidden`, `tabIndex`, `style`, `innerText`, события мыши/клавиатуры).
5. **Конкретные классы:** `HTMLInputElement`, `HTMLButtonElement`, `HTMLAnchorElement` и т.д., реализующие специфические свойства тегов (например, `input.value`, `a.href`).

### 5. Изменение документа.
* **Создание элементов:**
  * `document.createElement(tagName)` — создаёт элемент с указанным тегом.
  * `document.createTextNode(text)` — создаёт текстовый узел.
* **Вставка элементов в документ:**
  * `node.append(...nodes/strings)` — вставляет в конец родителя.
  * `node.prepend(...nodes/strings)` — вставляет в начало родителя.
  * `node.before(...nodes/strings)` — вставляет перед узлом.
  * `node.after(...nodes/strings)` — вставляет после узла.
  * `node.insertAdjacentHTML(position, htmlString)` — вставляет сырую разметку HTML в одну из 4 позиций: `"beforebegin"`, `"afterbegin"`, `"beforeend"`, `"afterend"`.
* **Удаление и замена:**
  * `node.remove()` — удаляет узел из DOM.
  * `parent.replaceChild(newNode, oldNode)` или `node.replaceWith(newNode)`.
* **Клонирование:**
  * `node.cloneNode(deep)` — клонирует узел (если `deep: true`, то вместе со всеми потомками).

### 6. События и их обработчики.
* **Событие (Event):** сигнал от браузера о том, что произошло определённое действие (клик мыши, нажатие клавиши, завершение загрузки документа, изменение размера окна).
* **Способы назначения обработчиков:**
  1. HTML-атрибут (устарело): `<button onclick="alert('1')">`.
  2. Свойство DOM-элемента: `btn.onclick = function() { ... };` (минус: нельзя назначить больше одного обработчика).
  3. **Современный стандарт:** `element.addEventListener(type, handler, [options])`:
     * Позволяет вешать неограниченное число независимых обработчиков.
     * Позволяет гибко управлять фазами (погружение/всплытие).
     * Снятие обработчика выполняется через `element.removeEventListener(type, handler)` (для этого передаваемая функция `handler` обязательно должна быть именованной ссылкой, а не анонимной стрелочной функцией).

### 7. Простые события пользовательского интерфейса (UIEvent).
`UIEvent` — базовый интерфейс для событий, возникающих при взаимодействии пользователя с графическим интерфейсом:
* `load` — ресурс и все зависимые файлы (стили, картинки) полностью загружены.
* `unload` / `beforeunload` — документ выгружается (закрытие страницы или переход по ссылке).
* `resize` — изменение геометрических размеров окна браузера (`window`).
* `scroll` — прокрутка страницы или отдельного блока с полосой прокрутки.
* От `UIEvent` наследуются более специализированные события:
  * `MouseEvent` (клики, перемещения курсора),
  * `KeyboardEvent` (`keydown`, `keyup`),
  * `FocusEvent` (`focus`, `blur`),
  * `TouchEvent` (касания сенсорного экрана).

### 8. Примеры свойств в объекте MouseEvent.
При возникновении событий мыши (`click`, `dblclick`, `mousedown`, `mouseup`, `mousemove`, `mouseenter`, `mouseleave`) в функцию-обработчик передаётся объект `MouseEvent`, содержащий следующие ключевые свойства:
1. `clientX`, `clientY` — координаты курсора относительно видимой области окна просмотра браузера (viewport) без учёта прокрутки.
2. `pageX`, `pageY` — координаты курсора относительно всего HTML-документа с учётом прокрутки.
3. `screenX`, `screenY` — координаты курсора относительно физического экрана монитора.
4. `button` — номер нажатой кнопки мыши (`0` — левая, `1` — средняя/колёсико, `2` — правая).
5. `buttons` — битовая маска всех удерживаемых кнопок мыши.
6. `target` — самый глубокий элемент, над которым непосредственно находился курсор при срабатывании события.
7. `relatedTarget` — вторичный элемент (откуда пришёл курсор для `mouseenter`/`mouseover` или куда ушёл для `mouseleave`/`mouseout`).
8. `altKey`, `ctrlKey`, `shiftKey`, `metaKey` — логические флаги (`true/false`), нажаты ли были соответствующие клавиши-модификаторы во время действия мыши.

## Лабораторная работа №3: Валидация данных в форме

### 1. Элемент dialog, методы showModal() и show().
Элемент `<dialog>` — это стандартный семантический HTML5-тег, предназначенный для создания всплывающих окон, модальных диалогов и подтверждений.
* **`dialog.showModal()`:**
  * Открывает окно в **модальном режиме**.
  * Автоматически добавляет псевдоэлемент подложки `::backdrop` (затемнение фона страницы).
  * Блокирует взаимодействие со всей остальной страницей: запрещает клики и фокус по элементам вне диалога (фокус удерживается внутри диалога — focus trap).
  * Позволяет закрывать окно по нажатию на клавишу `Escape`.
* **`dialog.show()`:**
  * Открывает окно в **немодальном режиме** (обычный всплывающий блок без затемнения).
  * Пользователь может продолжать свободно взаимодействовать с элементами остальной страницы.
* Для закрытия окна в обоих случаях вызывается метод `dialog.close([returnValue])`.

### 2. Фазы жизненного цикла события и опции при добавлении обработчика события.
При возникновении события в DOM оно проходит **3 последовательные фазы**:
1. **Фаза погружения (Capturing Phase):** событие спускается от корня (`window`, `document`) вниз по дереву предков к целевому элементу, на котором произошло действие.
2. **Фаза цели (Target Phase):** событие достигает самого глубокого целевого элемента (`event.target`).
3. **Фаза всплытия (Bubbling Phase):** событие поднимается вверх от целевого элемента обратно к корню документа, последовательно вызывая обработчики у всех предков.

**Опции метода `element.addEventListener(type, listener, [options])`:**
* `capture` (boolean): если `true`, обработчик перехватывает событие на фазе *погружения*; по умолчанию `false` (обработчик срабатывает на фазе *всплытия*).
* `once` (boolean): если `true`, обработчик автоматически удаляется после первого же срабатывания.
* `passive` (boolean): если `true`, указывает браузеру, что обработчик никогда не вызовет `preventDefault()` (критично для плавной прокрутки страниц на мобильных устройствах при событиях `touch` и `wheel`).
* `signal` (`AbortSignal`): позволяет централизованно отменить обработчик через `AbortController`.

### 3. Свойства target и currentTarget у объекта события.
* **`event.target`:**
  * Указывает на **исходный (целевой) элемент**, на котором непосредственно произошло событие (например, конкретная картинка или иконка внутри кнопки, по которой щёлкнул пользователь).
  * `target` остаётся неизменным на протяжении всех фаз погружения и всплытия.
* **`event.currentTarget` (то же, что и `this` в классической функции):**
  * Указывает на **элемент, на котором в данный момент выполняется обработчик события**.
  * При всплытии `currentTarget` меняется по мере того, как событие поднимается по родительским элементам.
* *Практическое применение:* используется в паттерне **делегирования событий**, когда один слушатель вешается на родительский список (`currentTarget = <ul>`), а кликнутый пункт определяется через `target.closest('li')`.

### 4. Объект FormData, примеры методов, перебор его свойств.
`FormData` — встроенный интерфейс, позволяющий собирать данные полей формы в формате пар «ключ: значение» для их валидации или отправки через AJAX/Fetch.
* **Создание:**
  ```javascript
  const formData = new FormData(formElement); // Автоматически собирает данные из формы
  ```
* **Методы объекта `FormData`:**
  * `formData.append(name, value, [filename])` — добавляет новое значение к ключу (не перезаписывает существующие с тем же именем).
  * `formData.set(name, value, [filename])` — устанавливает значение (перезаписывает существующее).
  * `formData.get(name)` — возвращает первое значение по ключу.
  * `formData.getAll(name)` — возвращает массив всех значений по ключу.
  * `formData.has(name)` — проверяет наличие ключа (`true/false`).
  * `formData.delete(name)` — удаляет поле по ключу.
* **Перебор свойств:**
  * Преобразование в обычный объект:
    ```javascript
    const data = Object.fromEntries(formData.entries());
    ```
  * Через цикл `for ... of`:
    ```javascript
    for (const [key, value] of formData) {
      console.log(`${key}: ${value}`);
    }
    ```

### 5. Предотвращение стандартного поведения элементов.
Многие элементы в браузере имеют поведение по умолчанию (переход по ссылке при клике на `<a>`, отправка формы и перезагрузка страницы при клике на `<button type="submit">`, открытие контекстного меню при правом клике).
* **Метод `event.preventDefault()`:**
  * Отменяет стандартное действие браузера для текущего события.
  * Пример:
    ```javascript
    form.addEventListener("submit", (e) => {
      e.preventDefault(); // Страница не перезагружается, отправку берет на себя JS
    });
    ```
* **Отличие от `stopPropagation()`:**
  * `preventDefault()` **не** останавливает всплытие события по дереву, а лишь отменяет действие браузера.
  * `stopPropagation()` прекращает движение события дальше по цепочке родителей, но не отменяет стандартное действие.

### 6. Атрибуты полей форм для добавления ограничений (HTML5 Constraint Validation).
* `required` — поле обязательно для заполнения (не может быть пустым при отправке).
* `minlength` и `maxlength` — минимальное и максимальное количество символов для текстовых полей.
* `min` и `max` — минимальное и максимальное числовое значение (для `type="number"`, `type="date"`).
* `step` — допустимый шаг изменения числового значения (например, `step="0.1"`).
* `type` — валидация семантического типа (`email`, `url`, `number`, `tel`).
* `pattern` — регулярное выражение, которому должно строго соответствовать введённое значение (например, `pattern="[0-9]{4}"`).

### 7. Цель и методы валидации данных на стороне клиента.
* **Цель клиентской валидации:**
  * Обеспечить мгновенную обратную связь для пользователя (UX), показывая ошибки сразу при вводе или потере фокуса.
  * Помочь пользователю правильно заполнить форму без лишних задержек сетевых запросов.
  * Разгрузить сервер от заведомо некорректных запросов.
  * *Важное правило безопасности:* клиентская валидация никогда не отменяет серверную валидацию, так как клиентский код может быть отключён или обойдён злоумышленником.
* **Методы валидации на клиенте:**
  1. *Встроенная браузерная валидация:* через HTML5-атрибуты (`required`, `type`, `pattern`).
  2. *Constraint Validation API:* программное управление валидностью через JavaScript (`checkValidity()`, `validity`, `setCustomValidity()`).
  3. *Кастомная валидация на JS:* регулярные выражения, сверка паролей, проверка взаимосвязанных полей.

### 8. Псевдоклассы для изменения стилей для полей формы при валидации и их отличия.
* `:valid` и `:invalid` — применяются к полю на основе его соответствия ограничениям.
  * *Минус:* поле с атрибутом `required` подсвечивается как `:invalid` сразу же при открытии страницы, ещё до того, как пользователь успел что-либо ввести, что ухудшает пользовательский опыт.
* `:user-valid` и `:user-invalid` (современный стандарт):
  * Срабатывают **только после того**, как пользователь совершил взаимодействие с полем (например, изменил текст и увёл фокус `blur`). До первого взаимодействия поле не считается `:user-invalid`, благодаря чему интерфейс остаётся чистым и доброжелательным.
* `:required` и `:optional` — выбирают обязательные и необязательные поля соответственно.

### 9. Aria-атрибуты: aria-describedby, aria-live и aria-invalid.
Эти атрибуты обеспечивают доступность (Accessibility / A11y) для скринридеров и людей с ограниченными возможностями:
1. **`aria-describedby="element-id"`:**
   * Связывает поле ввода с вспомогательным элементом (подсказкой или текстом ошибки). Скринридер прочитает текст из этого блока сразу после озвучивания имени поля.
2. **`aria-invalid="true"|"false"`:**
   * Сообщает ассистивным технологиям, что текущее значение поля не прошло валидацию.
3. **`aria-live="polite"|"assertive"`:**
   * Указывает скринридеру озвучить динамически появившийся текст внутри элемента:
     * `polite` — озвучить, когда пользователь сделает паузу (рекомендуется для сообщений об ошибках).
     * `assertive` — немедленно прервать речь и озвучить текст (для критических алертов).

### 10. Работа с сообщениями о валидности в Constraint Validation API.
В JS каждый элемент формы предоставляет следующие свойства и методы:
* **`input.validity` (объект `ValidityState`):** содержит булевы флаги о типах нарушений:
  * `validity.valueMissing` — нарушено правило `required`.
  * `validity.typeMismatch` — значение не соответствует `type` (`email` или `url`).
  * `validity.tooShort` / `tooLong` — длина текста вне диапазона `minlength` / `maxlength`.
  * `validity.rangeUnderflow` / `rangeOverflow` — число вне диапазона `min` / `max`.
  * `validity.patternMismatch` — значение не совпадает с `pattern`.
  * `validity.valid` — `true`, если поле полностью корректно.
* **`input.validationMessage`:** стандартное системное сообщение браузера о причине ошибки.
* **`input.checkValidity()`:** проверяет поле; если невалидно — возвращает `false` и генерирует событие `invalid`.
* **`input.setCustomValidity(message)`:** устанавливает собственное кастомное сообщение об ошибке. Если передать пустую строку `""`, поле снова считается валидным.

## Лабораторная работа №4: Promise

### 1. Стек вызова (Call Stack).
* **Стек вызова (Call Stack):** структура данных типа LIFO (Last In, First Out — последним пришёл, первым ушёл), которая отслеживает, какая функция в данный момент выполняется в однопоточном движке JavaScript (например, V8).
* При вызове функции в стек помещается так называемый *фрейм вызова* (содержащий аргументы и локальные переменные функции).
* Когда функция завершает выполнение (достигает `return` или конца тела), её фрейм выталкивается из стека.
* Переполнение стека (Stack Overflow) возникает при бесконечной рекурсии, когда превышается максимальный лимит памяти стека.

### 2. Функции обратного вызова (Callbacks).
* **Функция обратного вызова (Callback):** функция, которая передаётся в другую функцию в качестве аргумента, чтобы быть вызванной позже (при наступлении события, таймера или завершении операции).
* *Синхронные колбэки:* вызываются немедленно в месте вызова (например, в `array.forEach(item => ...)`).
* *Асинхронные колбэки:* регистрируются для отложенного вызова (например, в `setTimeout`, `addEventListener`).
* **Проблема «Callback Hell» (Ад обратных вызовов):** возникает, когда несколько асинхронных операций должны выполняться строго по очереди, приводя к глубокой лестничной вложенности функций `({ { { ... } } })`, в которой крайне трудно обрабатывать ошибки и читать код. Для решения этой проблемы были созданы Промисы (`Promise`).

### 3. Таймеры в JS. Создание и удаление.
Таймеры в JS не являются частью спецификации языка ECMAScript, а предоставляются средой окружения (Host Environment — Web API браузера или Node.js API):
1. **Одноразовый таймер:**
   * `const timerId = setTimeout(callback, delay, ...args)` — вызывает `callback` через указанное количество миллисекунд.
   * `clearTimeout(timerId)` — отменяет запланированный таймер до его срабатывания.
2. **Периодический таймер:**
   * `const intervalId = setInterval(callback, delay, ...args)` — регулярно повторяет вызов `callback` через каждые `delay` миллисекунд.
   * `clearInterval(intervalId)` — останавливает периодический таймер.

### 4. Замыкание и примеры применения.
* **Замыкание (Closure):** это комбинация функции и её лексического окружения (Lexical Environment), в котором она была создана. Функция запоминает переменные из своей внешней области видимости и сохраняет к ним доступ даже после того, как внешняя функция завершила своё выполнение.
* **Примеры применения:**
  1. *Инкапсуляция и приватные переменные:*
     ```javascript
     function createCounter() {
       let count = 0; // приватная переменная
       return {
         increment: () => ++count,
         getValue: () => count
       };
     }
     const counter = createCounter();
     counter.increment(); // 1
     // Прямой доступ к count снаружи невозможен
     ```
  2. *Фабрики функций и каррирование:* создание специализированных функций с заранее зафиксированными аргументами (`const add5 = createAdder(5)`).
  3. *Функции-декораторы:* задержка выполнения (`debounce`), ограничение частоты вызова (`throttle`), мемоизация/кеширование.

### 5. Асинхронное программирование в JS.
JavaScript является **однопоточным языком** (Single-threaded) — в основном потоке выполняется только один процесс за раз.
* Если бы длительные операции (запросы к серверу, чтение файлов, таймеры) выполнялись синхронно, интерфейс браузера полностью «зависал» бы (блокировался) на время ожидания.
* **Асинхронность** позволяет передать длительную задачу фоновым потокам браузера (Web API), освободив основной поток для отрисовки интерфейса и реакции на действия пользователя. Когда фоновая задача завершается, её результат ставится в очередь, и JS обрабатывает его, как только освободится стек вызовов.

### 6. Общий принцип работы Event Loop.
**Цикл событий (Event Loop)** — это механизм, который координирует выполнение кода, обработку событий и выполнение подзадач между Call Stack, Web API и Очередями задач.
* **Схема работы:**
  1. Выполняется весь синхронный код, находящийся в Call Stack.
  2. Если встречаются асинхронные вызовы (таймеры, события, fetch), браузерное окружение Web API забирает их на выполнение в фоне.
  3. По завершении фоновой работы колбэки попадают в очереди:
     * **Очередь микрозадач (Microtask Queue):** промисы (`.then()`, `.catch()`, `.finally()`), `queueMicrotask`, `MutationObserver`.
     * **Очередь макрозадач (Macrotask Queue / Task Queue):** таймеры (`setTimeout`, `setInterval`), события интерфейса, сетевые колбэки.
  4. Когда Call Stack полностью опустел:
     * Сначала Event Loop выгребает **ВСЕ микрозадачи** до последней (включая микрозадачи, порождённые другими микрозадачами).
     * Затем браузер при необходимости производит перерисовку экрана (Render/Repaint).
     * Затем Event Loop берет **одну макрозадачу** из очереди макрозадач и помещает её в Call Stack.
     * Цикл повторяется снова.

### 7. Объект Promise и его состояния.
`Promise` (обещание) — специальный объект JavaScript, представляющий результат будущей асинхронной операции.
* Промис всегда находится в одном из **3 взаимоисключающих состояний**:
  1. `pending` (ожидание) — начальное состояние, операция ещё выполняется.
  2. `fulfilled` (выполнено успешно) — операция завершилась успешно, промис вернул значение (`value`).
  3. `rejected` (отклонено с ошибкой) — операция завершилась неудачей, промис вернул причину ошибки (`error/reason`).
* Состояния `fulfilled` и `rejected` называются *settled* (завершёнными). Переход из них невозможен — промис может разрешиться только один раз.

### 8. Методы объекта Promise. Примеры их использования.
1. **Методы экземпляра:**
   * `.then(onFulfilled, onRejected)` — регистрирует обработчики успешного результата и ошибки (возвращает новый промис, образуя цепочку).
   * `.catch(onRejected)` — перехватывает ошибки в цепочке (аналог `.then(null, onRejected)`).
   * `.finally(onFinally)` — выполняется всегда после завершения промиса (удобно для отключения спиннеров загрузки).
2. **Статические методы класса `Promise`:**
   * `Promise.resolve(val)` / `Promise.reject(err)` — возвращают немедленно завершённый промис.
   * `Promise.all([p1, p2, ...])` — ждёт завершения всех промисов. Если хотя бы один упал — немедленно отклоняется (all-or-nothing).
   * `Promise.allSettled([p1, p2, ...])` — ждёт завершения всех промисов, независимо от ошибок, возвращая массив их статусов и значений.
   * `Promise.race([p1, p2, ...])` — возвращает результат самого первого завершившегося промиса (будь то успех или ошибка).
   * `Promise.any([p1, p2, ...])` — ждёт первого *успешного* промиса. Отклоняется только если упали все промисы (`AggregateError`).

## Лабораторная работа №5: Fetch

### 1. Определение и назначение AJAX.
* **AJAX (Asynchronous JavaScript and XML):** концепция и технологический подход к веб-разработке, позволяющий веб-страницам асинхронно отправлять запросы к серверу и получать данные в фоновом режиме **без полной перезагрузки веб-страницы**.
* **Назначение AJAX:**
  * Создание плавных, отзывчивых и быстрых веб-приложений (SPA — Single Page Applications).
  * Динамическая подгрузка контента (бесконечная лента новостей, галереи, поиск с автодополнением).
  * Отправка форм и сохранение данных без потери состояния интерфейса и скролла.
  * Хотя исторически в названии фигурирует `XML`, сегодня абсолютным стандартом обмена данными в AJAX является формат `JSON`.

### 2. Fetch API (функция и ее параметры, используемые объекты).
`Fetch API` — современный стандарт браузера для выполнения сетевых HTTP-запросов (заменивший старый и громоздкий объект `XMLHttpRequest`).
* **Базовый синтаксис функции `fetch`:**
  ```javascript
  const promise = fetch(resource, [options]);
  ```
* **Параметры:**
  1. `resource` (string | Request): URL-адрес эндпоинта или готовый объект `Request`.
  2. `options` (объект настроек запроса):
     * `method`: HTTP-метод (`"GET"`, `"POST"`, `"PUT"`, `"DELETE"`, `"PATCH"` и т.д., по умолчанию `"GET"`).
     * `headers`: заголовки запроса (объект или экземпляр класса `Headers`), например `{ "Content-Type": "application/json" }`.
     * `body`: тело запроса (строка JSON, `FormData`, `Blob`, `URLSearchParams`). Для GET/HEAD методов тело не передаётся.
     * `mode`: режим CORS (`"cors"`, `"no-cors"`, `"same-origin"`).
     * `credentials`: отправка кук (`"same-origin"`, `"include"`, `"omit"`).
     * `cache`: управление кэшированием (`"default"`, `"no-store"`, `"reload"` и др.).
     * `signal`: экземпляр `AbortSignal` для отмены сетевого запроса.
* **Используемые интерфейсы/объекты:**
  * `Request` — представление HTTP-запроса.
  * `Response` — представление HTTP-ответа сервера.
  * `Headers` — работа с заголовками.
  * *Важная особенность fetch:* промис отклоняется (`reject`) **только при сетевом сбое** (обрыв связи, DNS-ошибка). Если сервер вернул HTTP-ошибку со статусом `404` или `500`, промис считается успешно выполненным (`resolve`), а проверку статуса нужно делать вручную через `response.ok`.

### 3. Объект Response. Его свойства и методы.
Объект `Response` создаётся браузером при получении ответа от сервера:
* **Свойства объекта `Response`:**
  * `response.status` — числовой код статуса HTTP (например, `200`, `400`, `404`, `500`).
  * `response.ok` — булево значение: `true`, если статус находится в диапазоне `200–299`, иначе `false`.
  * `response.statusText` — текстовое описание статуса (например, `"OK"`, `"Not Found"`).
  * `response.headers` — объект `Headers` с заголовками ответа сервера.
  * `response.url` — итоговый URL-адрес ответа (с учётом возможных редиректов).
* **Методы для чтения тела ответа (каждый возвращает Promise и может быть вызван только один раз):**
  * `response.json()` — парсит тело ответа как JSON и возвращает JavaScript-объект/массив.
  * `response.text()` — возвращает тело ответа в виде сырого текста.
  * `response.blob()` — возвращает данные в виде бинарного объекта `Blob` (изображения, аудио, файлы).
  * `response.formData()` — возвращает тело в виде объекта `FormData`.
  * `response.arrayBuffer()` — низкоуровневое двоичное представление данных.

### 4. Формат JSON. Глобальный объект JSON и его методы.
* **JSON (JavaScript Object Notation):** универсальный текстовый формат обмена данными, основанный на подмножестве синтаксиса объектов JavaScript.
  * *Правила синтаксиса JSON:*
    * Имена ключей **всегда** должны быть заключены в двойные кавычки `""`.
    * Одинарные кавычки `''` и обратные кавычки запрещены.
    * Допустимые типы значений: `string`, `number`, `boolean`, `null`, `object`, `array`.
    * Запрещены: функции, `undefined`, `NaN`, `Infinity`, символы `Symbol`, циклические ссылки, висячие запятые (trailing commas).
* **Глобальный объект `JSON` и его методы:**
  1. `JSON.stringify(value, [replacer], [space])` — сериализует объект/значение JS в JSON-строку:
     * `space` — число пробелов для красивого форматирования с отступами: `JSON.stringify(data, null, 2)`.
  2. `JSON.parse(text, [reviver])` — десериализует JSON-строку обратно в соответствующую структуру JavaScript (объект, массив, число, строку).

### 5. Хранение данных на клиенте.
Браузер предоставляет несколько механизмов для долговременного и сессионного сохранения данных:
1. **Cookies (Куки):** небольшие строки (до 4 Кб), передаются на сервер с каждым HTTP-запросом. Используются для сессий и авторизации.
2. **Web Storage API (`localStorage` и `sessionStorage`):** простое строковое хранилище типа «ключ-значение» (до 5–10 Мб на домен).
3. **IndexedDB:** мощная встроенная транзакционная NoSQL-база данных для хранения больших объёмов структурированных данных, файлов и блобов.
4. **Cache API:** специализированное хранилище для пар «Request / Response» (активно применяется сервис-воркерами в PWA для оффлайн-работы).

### 6. localStorage и sessionStorage. Разница, их методы.
Оба объекта реализуют интерфейс `Storage`:
* **Разница между ними:**
  * **`localStorage`:** постоянное хранилище. Данные сохраняются бессрочно: они не удаляются при закрытии вкладки или браузера и сохраняются даже после перезагрузки компьютера (пока их явно не удалит скрипт или пользователь). Доступно всем вкладкам одного источника (origin: протокол + домен + порт).
  * **`sessionStorage`:** сессионное хранилище. Данные существуют только в рамках текущей вкладки браузера. При закрытии вкладки данные полностью удаляются. Другие вкладки (даже с тем же сайтом) имеют изолированные сессионные хранилища.
* **Методы интерфейса `Storage`:**
  * `setItem(key, value)` — сохраняет значение по ключу (значение автоматически приводится к строке).
  * `getItem(key)` — возвращает строку по ключу (или `null`, если ключ отсутствует).
  * `removeItem(key)` — удаляет ключ и его значение.
  * `clear()` — полностью очищает всё хранилище текущего источника.
  * `key(index)` — возвращает имя ключа по порядковому номеру.
  * `length` — количество сохранённых записей.
* **Событие `storage`:** срабатывает в других вкладках того же сайта при изменении данных в `localStorage`, позволяя синхронизировать состояние между вкладками.

### 7. Асинхронные функции async/await. Возвращаемые значения.
Конструкция `async/await` (ES2017) — это синтаксический сахар над промисами, позволяющий писать асинхронный код так же просто и понятно, как и синхронный.
* **Ключевое слово `async`:**
  * Ставится перед объявлением функции.
  * Указывает, что функция **всегда возвращает Promise**. Если функция возвращает обычное значение, JS автоматически заворачивает его в `Promise.resolve(значение)`:
    ```javascript
    async function getData() { return 42; }
    getData().then(v => console.log(v)); // 42
    ```
* **Ключевое слово `await`:**
  * Может использоваться только внутри `async`-функции (или на верхнем уровне модулей Top-Level Await).
  * Приостанавливает выполнение текущей функции до тех пор, пока промис справа не перейдёт в состояние `fulfilled` или `rejected`.
  * При успехе возвращает разрешённое значение промиса.
  * При ошибке выбрасывает исключение, которое перехватывается классическим блоком `try { ... } catch (error) { ... }`.

### 8. Проблема «цветных» функций (Function Coloring).
Концепция введена программистом Бобом Нистромом (Bob Nystrom) в статье *"What Color is Your Function?"*.
* **Суть проблемы:** функции в языке программирования разделяются на два несовместимых «цвета»:
  1. *«Синие» (синхронные функции):* возвращают значение немедленно.
  2. *«Красные» (асинхронные функции — `async`):* возвращают Promise и требуют использования `await`.
* **Правила несовместимости:**
  * «Красная» функция легко может вызывать «синюю».
  * Но «синяя» (синхронная) функция **не может** синхронно получить значение из «красной» (асинхронной) функции без использования `await`, что немедленно делает саму эту функцию «красной».
* Таким образом, появление хотя бы одного асинхронного вызова глубоко в архитектуре программы «окрашивает» всю цепочку вызывающих функций наверх в асинхронный цвет, вынуждая переписывать сигнатуры функций на `async`.

## Лабораторная работа №6: Classes, SSE

### 1. Server-Sent Events (SSE). Принцип работы, заголовки, формат сообщений.
* **SSE (Server-Sent Events — События, отправляемые сервером):** стандарт передачи одностороннего потока данных в реальном времени от сервера к клиенту поверх обычного HTTP-соединения. В отличие от WebSockets, канал связи **однонаправленный** (сервер вещает, клиент слушает).
* **Принцип работы:** клиент отправляет стандартный HTTP-запрос, сервер держит соединение открытым бесконечно долго и отправляет порции данных по мере их появления.
* **Заголовки HTTP:**
  * Заголовок ответа сервера:
    ```http
    Content-Type: text/event-stream; charset=utf-8
    Cache-Control: no-cache
    Connection: keep-alive
    ```
* **Формат сообщений (plain text):**
  * Сообщения разделяются **двойным переводом строки (`\n\n`)**.
  * Каждая строка начинается с предопределённого поля:
    * `data: <полезная нагрузка>` — данные сообщения (часто JSON). Если данных несколько строк, каждая начинается с `data:`.
    * `event: <имя_события>` — кастомный тип события (для вызова отдельного слушателя событий).
    * `id: <идентификатор>` — ID сообщения. При разрыве связи клиент автоматически отправляет заголовок `Last-Event-ID` для дозагрузки пропущенных данных.
    * `retry: <миллисекунды>` — время ожидания перед повторным автоматическим переподключением клиента.
    * `: <комментарий>` — строки, начинающиеся с двоеточия, игнорируются (используются как ping/heartbeat).

### 2. Объект EventSource. Возможности, методы, события.
Интерфейс `EventSource` — встроенный в браузер клиент для работы с Server-Sent Events:
* **Создание соединения:**
  ```javascript
  const sse = new EventSource("/api/stream", { withCredentials: false });
  ```
* **Возможности:**
  * Автоматическое переподключение (auto-reconnect) при обрыве связи.
  * Восстановление потока с последнего полученного сообщения через `Last-Event-ID`.
  * Лёгкая интеграция с событийной моделью DOM (`addEventListener`).
* **События:**
  * `open` (`sse.onopen`) — соединение успешно установлено.
  * `message` (`sse.onmessage`) — получено стандартное сообщение без указания поля `event`.
  * `<customEvent>` (`sse.addEventListener("customEvent", handler)`) — получено именованное событие, заданное полем `event: customEvent`.
  * `error` (`sse.onerror`) — возникла сетевая ошибка или сервер закрыл соединение.
* **Методы:**
  * `sse.close()` — закрывает соединение и останавливает попытки авто-переподключения.
* **Свойства:**
  * `sse.readyState` — статус: `0` (`CONNECTING`), `1` (`OPEN`), `2` (`CLOSED`).

### 3. Идея реактивности при разработке пользовательских интерфейсов.
* **Реактивность (Reactivity):** парадигма программирования, при которой изменение состояния данных (State) автоматически приводит к обновлению всех зависящих от него частей интерфейса (UI) и вычислений без необходимости вручную искать DOM-элементы и менять их свойства.
* *Сравнение:*
  * *Императивный подход:* при изменении баланса нужно найти `<span id="balance">`, преобразовать число в строку и вручную обновить `textContent`.
  * *Реактивный подход:* мы просто меняем переменную `state.balance = 500`, а система сама отслеживает эту зависимость и обновляет только те узлы DOM, которые зависят от баланса.
* В современных UI-фреймворках (Vue, React, Solid, Angular) и нативном JS реактивность строится на паттернах:
  * Проксирование объектов (`Proxy` в JavaScript).
  * Аксессоры (геттеры и сеттеры `get`/`set`).
  * Сигналы (Signals).
  * Паттерн «Наблюдатель» (Observer / Publish-Subscribe).

### 4. Шаблон «Наблюдатель» (Observer Pattern).
Паттерн проектирования, определяющий зависимость типа «один ко многим» между объектами таким образом, что при изменении состояния одного объекта (Издатель / Subject) все зависящие от него объекты (Наблюдатели / Observers) автоматически оповещаются и обновляются.
* **Составляющие паттерна:**
  1. **Subject (Издатель / Observable):**
     * Хранит список наблюдателей: `private observers = []`.
     * Метод подписки: `subscribe(observer)` (или `attach`).
     * Метод отписки: `unsubscribe(observer)` (или `detach`).
     * Метод оповещения: `notify(data)` — циклически вызывает метод `update` у каждого зарегистрированного наблюдателя.
  2. **Observer (Наблюдатель):**
     * Предоставляет метод интерфейса `update(data)`, вызываемый издателем при обновлении.

### 5. Функция-конструктор. Свойство prototype. Создание объекта.
До появления синтаксиса классов в ES6 объектно-ориентированное программирование в JS строилось на функциях-конструкторах:
* **Функция-конструктор (Constructor Function):**
  * Обычная функция, которая по соглашению именуется с заглавной буквы и вызывается с помощью оператора `new`.
  * Внутри неё неявно создаётся пустой объект, который привязывается к ключевому слову `this`, и неявно возвращается в конце:
    ```javascript
    function User(name, age) {
      this.name = name;
      this.age = age;
    }
    ```
* **Свойство `prototype`:**
  * У каждой функции в JS есть объект-свойство `.prototype`.
  * Все методы, записанные в `User.prototype`, будут доступны всем экземплярам через цепочку прототипов (`__proto__`), что экономит память (метод не дублируется в каждом объекте):
    ```javascript
    User.prototype.sayHi = function() {
      console.log(`Привет, я ${this.name}`);
    };
    const user1 = new User("Иван", 20);
    user1.sayHi(); // Находит метод в User.prototype
    ```

### 6. Создание класса, наследование, задача функции super(), создание экземпляра.
В стандарте ES6 (2015) был добавлен синтаксис ключевого слова `class` (синтаксический сахар над прототипным наследованием):
* **Создание класса:**
  ```javascript
  class Animal {
    constructor(name) {
      this.name = name;
    }
    makeSound() {
      console.log(`${this.name} издаёт звук`);
    }
  }
  ```
* **Наследование через ключевое слово `extends`:**
  ```javascript
  class Dog extends Animal {
    constructor(name, breed) {
      super(name); // Вызов конструктора родительского класса
      this.breed = breed;
    }
    makeSound() {
      super.makeSound(); // Вызов метода родителя
      console.log(`${this.name} лает: Гав-гав!`);
    }
  }
  ```
* **Задача функции `super()`:**
  1. Вызывает конструктор родительского класса (`Animal.constructor`), инициализируя родительские свойства.
  2. В производном классе обращение к `this` **запрещено** до тех пор, пока не будет вызван `super()`, так как именно родительский конструктор создаёт объект `this`.
* **Создание экземпляра класса:**
  * Выполняется через оператор `new`: `const rex = new Dog("Рекс", "Овчарка");`.

### 7. Поля и методы классов. Приватные поля и методы, статические методы.
В современных спецификациях JavaScript классы поддерживают:
1. **Публичные поля и методы:**
   * Доступны снаружи экземпляра класса (`this.name`, `this.getName()`).
2. **Приватные поля и методы (префикс `#`):**
   * Объявляются с символом решётки `#` перед именем.
   * Доступны **строго внутри** самого класса; попытка обратиться к ним снаружи (`instance.#secretField`) вызывает синтаксическую ошибку `SyntaxError`:
     ```javascript
     class BankAccount {
       #balance = 0; // Приватное поле

       #logOperation(type) { // Приватный метод
         console.log(`Операция: ${type}`);
       }

       deposit(amount) {
         this.#balance += amount;
         this.#logOperation("deposit");
       }

       getBalance() {
         return this.#balance;
       }
     }
     ```
3. **Статические поля и методы (ключевое слово `static`):**
   * Принадлежат самому классу как объекту, а не его экземплярам.
   * Вызываются напрямую через имя класса: `ClassName.staticMethod()`.
   * Часто используются для фабричных методов (`User.createAdmin()`), констант или вспомогательных утилит (как в классе `Math.max()`).
4. **Аксессоры (геттеры и сеттеры `get` / `set`):**
   * Позволяют определять функции, которые снаружи синтаксически выглядят как обычные свойства:
     ```javascript
     class User {
       get fullName() { return `${this.first} ${this.last}`; }
       set fullName(val) { [this.first, this.last] = val.split(" "); }
     }
     ```
